# 双机联机测试指南

这份清单用于验证实验版，不代表以下行为已成功。

## 准备

两台 Windows PC、同一局域网、相同 Steam 游戏构建 25754144、相同版本 Blueprint Loader、同一个 0.1.1 Release 的 NativeBridge 与 LanDirect 两个包。旧本机验证使用 Blueprint Loader 2.3，2.5 尚未回归验证。双方先退出游戏并安装；确认安装程序显示了存档备份路径。建议建立测试用离线英雄。

记录双方游戏版本和英雄等级。开服电脑用 `ipconfig` 查看实际网卡的 IPv4；加入端不要填写 127.0.0.1、网关地址或 VPN 网卡地址。

## 按顺序验证

1. 双方主菜单出现“本地开服”和“加入本地游戏”，字体、边框和按钮样式正常。
2. 开服端填 7777，点击“创建大厅”；成功后点击原版“开始游戏”，记录能否正常进入世界、角色装备是否一致。首轮让加入端在主机进入主世界后再加入；大厅加入另行测试。
3. 加入端填开服端 IPv4:7777，点击“加入并进入”，记录出现的提示、耗时、是否进入相同世界。
4. 双方移动并互相确认位置；再检查战斗、受伤、掉落与物品拾取。
5. 开服端切换地图，确认另一端是否一同进入、角色是否还在。
6. 加入端先正常退出，开服端再正常退出。分别重进离线模式，确认角色进度和物品。
7. 独立验证不可达地址、取消连接和超时返回，不在正常联机流程中混测。

只完成某一步就只报告那一步，不要把“有监听端口”当作“联机成功”。如果加入失败，优先记录提示和日志，不反复恢复整个旧存档。

## 主菜单英雄切换回归

使用测试用离线英雄，先检查主菜单的两个 LAN 按钮，再反复切换英雄至少五次（包括打开英雄选择后取消）。每次返回主菜单等待约半秒，应只有一组“本地开服”和“加入本地游戏”，位于原版“开始游戏”之后。分别打开两个弹窗并取消，确认一次点击只打开一次，原版开始和取消仍正常。

建立本地大厅后再切换英雄，应保留一组“关闭本地大厅”和“加入本地游戏”。关闭大厅返回后，再检查普通开服标签。此项只验证菜单生命周期，不代表英雄同步或双机联机成功。

自动回归：`./tests/Test-MenuLifecycle.ps1` 使用模拟引擎对象执行源码中的实际挂载方法，覆盖新菜单、原菜单子控件重建、部分按钮移除、重复轮询、点击委托和大厅标签。NeoRune 构建另行检查真实引擎绑定；渲染和游戏内英雄切换仍需上述手动测试。

## 本机地牢对比测试

在退出游戏、备份最新存档后，使用同一测试用离线英雄和相同地牢入口：

1. 通过普通“开始游戏”进入世界，记录角色装备、地牢名称、进入与退出是否完成。
2. 返回主菜单，点击“本地开服”。主菜单大厅候选应停留在大厅，等用户点击原版“开始游戏”后进入世界；检查角色装备与普通开始一致，并检查 UDP 监听。此流程仍处于验证阶段。
3. 进入同一地牢，退出并再次进入。记录是否卡在加载，以及等待时间。
4. 分开记录原版流程、本地 listen 链路、地牢加载结果；不能只凭编译成功或角色生成宣称修复。

若同一个入口重启后未出现或未启用，记录这一差异，该次不能作为同入口加载对照。先选择另一个仍然有效的地牢确认普通模式能否进入，之后再复测开服状态。

若角色关联检查失败自动返回主菜单，保留诊断并停止该次测试，不跳过检查继续游戏。

## 本机只读检查

开服后在 PowerShell 执行：

```powershell
$game = Get-Process -Name Dungeons-Win64-Shipping -ErrorAction Stop | Where-Object { -not $_.HasExited }
Get-NetUDPEndpoint -OwningProcess $game.Id | Where-Object LocalPort -eq 7777
```

出现监听地址只说明本机开服成功，仍需要另一台电脑验证加入。必要时查看 `%LOCALAPPDATA%\Dungeons2\Saved\Logs` 下最新日志（若游戏生成）。分享前删除账户名、个人路径及地址等私人信息。
